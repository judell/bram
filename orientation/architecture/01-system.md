## You

Bram's README says it is for "Anyone who uses Claude Code, Codex and/or OpenCode." [`README.md:11-13`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L11-L13) You start it from the root of a git repo: "Anywhere else (your home directory, a folder that isn't a git repo, or a subfolder of one), Bram starts nothing and says where to start from." [`README.md:95-98`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L95-L98) The host enforces this in `run_enhance`, which refuses with "Setup refused" outside a repo root. The repo doesn't say how many people use Bram or on which platforms beyond the build matrix in the release workflow (see diagram 6).

## Agent pane

Bram's own UI. The host page puts a terminal and two iframes side by side: `right-pane` (the target app) and `tools-pane` (the agent pane). [`app/index.html:31-53`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/index.html?plain=1#L31-L53) The agent pane is an XMLUI app; its navigation lists Worklist, Transcript, Sessions, Issues, Commits, Queue, Search, Alerts, History, Files, Settings, Tips, Context and Status. [`app/tools/Main.xmlui:685-728`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/tools/Main.xmlui?plain=1#L685-L728) Each tab is a routed `Page`. [`app/tools/Main.xmlui:1010-1022`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/tools/Main.xmlui?plain=1#L1010-L1022)

State placement is a stated design line: "The shell owns the agent-session context and all expensive shared data. Pages are disposable lenses over it." [`docs/session-context-architecture.md:44-46`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/session-context-architecture.md?plain=1#L44-L46) That doc names four layers (native shell, host page, agent-pane App scope, Pages). [`docs/session-context-architecture.md:8-40`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/session-context-architecture.md?plain=1#L8-L40)

## Tauri shell

The Rust host. `run()` registers two custom URI schemes (`tauri` and `bramapp`), lists the IPC commands the pane may invoke, and binds the HTTP server. [`src-tauri/src/lib.rs:88585-88585`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88585-L88585) [`src-tauri/src/lib.rs:88639-88694`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88639-L88694) The session-context doc describes it as the layer that "Owns the PTY, the agent process, turn-state detection, and pushes Tauri events." [`docs/session-context-architecture.md:13-16`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/session-context-architecture.md?plain=1#L13-L16)

The release doc describes the host as large: "The Rust host is large and carries most of Bram's logic". [`docs/releasing.md:3-5`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/releasing.md?plain=1#L3-L5) At this commit `src-tauri/src/lib.rs` is 92,380 lines (`git show b2eb8e0b:src-tauri/src/lib.rs | wc -l`), with `guard.rs`, `guard_policy.rs`, `worklist_state.rs`, `search_index.rs` and `grant_lifecycle.rs` beside it.

## Loopback server

An HTTP server on `127.0.0.1`. The host tries the previous run's port first, so allowlist entries that name literal ports keep working, and otherwise takes an ephemeral port. [`src-tauri/src/lib.rs:88707-88747`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88707-L88747) It publishes the port to `resources/.bram-port` "only after the accept loop is actually serving HTTP." [`src-tauri/src/lib.rs:88935-88939`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88935-L88939) Each request is handled on its own thread. [`src-tauri/src/lib.rs:88931-88932`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88931-L88932) Routes are dispatched in `handle_http` and `route_request`. [`src-tauri/src/lib.rs:87635-87646`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L87635-L87646) [`src-tauri/src/lib.rs:75896-75900`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L75896-L75900)

Browser boundaries: the response header that allows cross-origin reads is echoed only for the shell origin ("ACAO is now echoed only for the shell origin"). [`src-tauri/src/lib.rs:87648-87659`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L87648-L87659) A same-user process is not covered: "a same-user process is not CORS-bound", which the security assessment accepts as a residual. [`docs/authorization.md:42-45`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/authorization.md?plain=1#L42-L45)

Request gate: before any route runs, `handle_http` calls `loopback_gate_refusal`, which answers 403 to a state-changing request whose `Origin` is not the shell's, and to any request whose `Host` is not `127.0.0.1` or `localhost` at this instance's port. [`src-tauri/src/lib.rs:87661-87689`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L87661-L87689) [`src-tauri/src/lib.rs:88046-88060`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88046-L88060) A request with no `Origin` passes, as do the pane's own fetches, hooks and curl: "No-Origin callers pass". [`src-tauri/src/lib.rs:88005-88011`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88005-L88011) State changes are every method other than GET, HEAD and OPTIONS, plus a hand-kept list of GET paths that act (`STATE_CHANGING_GET_PATHS`). [`src-tauri/src/lib.rs:88021-88028`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88021-L88028) Refusals are traced as `loopback-refusal`. [`src-tauri/src/lib.rs:87676-87689`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L87676-L87689) The gate adds no caller identity: "The loopback gate stops pages, not local processes." [`docs/authorization.md:235-235`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/authorization.md?plain=1#L235-L235) Security assessment H6 records the send half as closed and the local-process residual as accepted. [`docs/security.md:326-326`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/security.md?plain=1#L326-L326)

## HTTP routes

The agent pane's `/__*` requests go to `tauri://localhost`; the scheme handler proxies any path starting with `__` to the loopback server (its "Tier 3"). [`src-tauri/src/lib.rs:88234-88249`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88234-L88249) Agents call the same server with `curl`, reading the port from `resources/.bram-port`. [`app/__shell/conventions.md:411-420`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/__shell/conventions.md?plain=1#L411-L420) The repo doesn't give a complete route list in one place; `docs/apis.md` is the nearest thing, a catalog that says of itself "Code is the source of truth; this is the announcement surface." [`docs/apis.md:72-73`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/apis.md?plain=1#L72-L73) Nothing in `src-tauri/`, `scripts/` or `.github/` reads it to check it against `handle_http` (the only mentions of the file in the Rust and scripts are a test that keeps the seeded conventions from pointing at it), so its completeness rests on whoever adds a route updating it. [`src-tauri/src/lib.rs:91942-91942`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L91942-L91942)

## Worklist calls

This is how an agent advances, prunes or commits an item. Claude and OpenCode use loopback curl. [`app/__shell/conventions.md:413-413`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/__shell/conventions.md?plain=1#L413-L413) Codex's `workspace-write` sandbox refuses loopback connections, so it writes `resources/.worklist-intent.json` and reads a result file. Both transports reach the same host-side handlers, so the checks are identical. [`app/__shell/reference/worklist-mechanics.md:250-257`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/__shell/reference/worklist-mechanics.md?plain=1#L250-L257)
