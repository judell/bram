# Bram: an overview for newcomers (Update 2026-10-31)

Bram is a desktop workspace for AI-assisted development, from the repository `judell/bram` on GitHub. Its README opens: "Agentic software development on human terms: legible, orderly, transparent, accountable, and collaborative." [`README.md:5-5`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L5-L5) It is for "Anyone who uses Claude Code, Codex and/or OpenCode." [`README.md:11-13`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L11-L13)

This overview is a reader's map, not part of the project. It was written with Bram on 2026-10-31, reading the repository as of commit `b2eb8e0b` (2026-10-31). Every claim cites a file and line range at that commit. Where the repo is silent, this says so rather than guessing. The repository is Apache-2.0 licensed and has no `NOTICE` file at the repo root (`git ls-tree b2eb8e0b`). [`LICENSE:1-2`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/LICENSE?plain=1#L1-L2) The **Architecture** tab has six diagrams with click-through detail: system at a glance, a turn's lifecycle, the Worklist gate, state and data, providers, and build, run and release. In each, solid arrows are what code does on its own and dashed arrows are what happens only if a person or agent remembers.

## What it is

The parts, in a short list:

- **A Tauri desktop shell in Rust.** It owns the pseudo-terminal, the agent process, turn-state detection and the push of events to the UI. [`docs/session-context-architecture.md:13-16`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/session-context-architecture.md?plain=1#L13-L16) Its entry point is `run()` in `src-tauri/src/lib.rs`. [`src-tauri/src/lib.rs:88585-88585`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88585-L88585) At this commit `lib.rs` is 92,380 lines (`git show b2eb8e0b:src-tauri/src/lib.rs | wc -l`), beside `guard.rs`, `guard_policy.rs`, `worklist_state.rs`, `search_index.rs` and `grant_lifecycle.rs`. `docs/releasing.md` describes the host the same way: "The Rust host is large and carries most of Bram's logic". [`docs/releasing.md:3-5`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/releasing.md?plain=1#L3-L5)
- **A terminal with the agent CLI in it.** `claude`, `codex` or `opencode`, run in a PTY and shown with xterm.js; optional to look at and closed by default. [`src-tauri/src/lib.rs:27334-27341`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L27334-L27341) [`README.md:19-25`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L19-L25)
- **An agent pane built in XMLUI.** The tabs are Worklist, Transcript, Sessions, Issues, Commits, Queue, Search, Alerts, History, Files, Settings, Tips, Context and Status. [`app/tools/Main.xmlui:685-728`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/tools/Main.xmlui?plain=1#L685-L728)
- **The Worklist gate.** Every change goes from proposal, to altered files, to a commit or a drop, "and hooks hold the agent to that order: no file alterations without an approved item, no commit without your approval." [`README.md:68-68`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L68-L68) A Rust binary, `bram-guard`, is the hook. [`src-tauri/src/guard.rs:1-13`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/guard.rs?plain=1#L1-L13) `guard.rs` says its deciding hooks are "the sole implementation since retire-python-hooks-rust-only". [`src-tauri/src/guard.rs:1-5`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/guard.rs?plain=1#L1-L5) The header of `guard_policy.rs` says the module "began as a shadow port" of a Python guard, since retired, and that "The decision pipeline here is now the implementation." [`src-tauri/src/guard_policy.rs:1-6`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/guard_policy.rs?plain=1#L1-L6)
- **Git as infrastructure.** Git is also Bram's "dirty-state model, transaction engine, attribution ledger, snapshot store, fixture format, and part of its cross-process coordination layer." [`docs/git-as-infrastructure.md:3-6`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/git-as-infrastructure.md?plain=1#L3-L6)
- **A loopback HTTP server and a search index** for state the pane and agents share. Its common gate, `loopback_gate_refusal`, refuses state changes that carry a foreign `Origin`, and any `Host` that is not loopback at this port. [`src-tauri/src/lib.rs:88046-88060`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88046-L88060) [`src-tauri/src/lib.rs:88707-88747`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L88707-L88747) [`app/__shell/conventions.md:728-730`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/app/__shell/conventions.md?plain=1#L728-L730) `docs/apis.md` is the route catalog: every `__` route string that `route_request` and `handle_http` name appears in it. [`docs/apis.md:1-5`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/apis.md?plain=1#L1-L5) [`src-tauri/src/lib.rs:75896-75896`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L75896-L75896) [`src-tauri/src/lib.rs:87635-87635`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L87635-L87635)

## How it runs

You start Bram from the root of a git repo. "Anywhere else (your home directory, a folder that isn't a git repo, or a subfolder of one), Bram starts nothing and says where to start from." [`README.md:95-98`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L95-L98) `gh` powers the Issues tab. [`README.md:103-107`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L103-L107) Install is a script that "verifies the archive's SHA256 against the published `SHA256SUMS`". [`README.md:119-125`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L119-L125)

For developers, builds are debug builds, always: "Always `cargo build` (debug), never `cargo build --release`, when validating changes". [`docs/developing-bram.md:480-482`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/developing-bram.md?plain=1#L480-L482) Under the documented `./bram` symlink launch, everything under `app/` is served from disk, so pane edits show on reload; only `src-tauri/**` needs a rebuild and relaunch. [`docs/developing-bram.md:439-445`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/developing-bram.md?plain=1#L439-L445) Releases are cut by `scripts/bump.sh` and a `workflow_dispatch`-only GitHub workflow. [`docs/releasing.md:14-24`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/releasing.md?plain=1#L14-L24) See diagram 6. The symlink is gitignored as a "Local launcher symlink to the current debug build" [`.gitignore:26-27`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/.gitignore?plain=1#L26-L27); `scripts/build.sh` creates it after a successful build, with the comment "nothing else creates it". [`scripts/build.sh:118-123`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/scripts/build.sh?plain=1#L118-L123)

No shipped form uses the `resources: ["../app"]` bundle setting in `tauri.conf.json`. [`src-tauri/tauri.conf.json:26-28`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/tauri.conf.json?plain=1#L26-L28) Releases run `cargo build` and then `tar` only `bram` and `bram-guard`. [`.github/workflows/build.yml:269-269`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/.github/workflows/build.yml?plain=1#L269-L269) [`.github/workflows/build.yml:281-281`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/.github/workflows/build.yml?plain=1#L281-L281) With no `app/` directory beside the binary, the runtime falls back to the embedded tree (diagram 6).

The project homepage is <https://judell.github.io/bram/>, which the README links. [`README.md:15-15`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/README.md?plain=1#L15-L15) The `pages.yml` workflow publishes `site/` there. [`.github/workflows/pages.yml:1-1`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/.github/workflows/pages.yml?plain=1#L1-L1)

Setup is a one-time step per project that seeds conventions, reference docs, hook registrations and instruction files for each provider. [`src-tauri/src/lib.rs:55707-55729`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/src-tauri/src/lib.rs?plain=1#L55707-L55729) [`docs/setup.md:3-15`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/setup.md?plain=1#L3-L15) `GET /__enhance/status` says which check failed: `setupReasons` carries stable codes and `providerSetupKind` can read `restart-older-process`. [`docs/developing-bram.md:721-728`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/developing-bram.md?plain=1#L721-L728) See diagrams 5 and 6.

The pane's browser storage splits into decisions (`localStorage`) and focus (`sessionStorage`), and project data should carry a project suffix. [`docs/developing-bram.md:286-300`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/developing-bram.md?plain=1#L286-L300) The doc records an audit of the unscoped keys on 2026-10-31: two project keys, `bram.worklistSubmittedMessage` and its `Kind` twin, turned up, but nothing read them, "so they were deleted, not scoped." [`docs/developing-bram.md:317-321`](https://github.com/judell/bram/blob/b2eb8e0b702970b3cfb160702268c51395cbe319/docs/developing-bram.md?plain=1#L317-L321)
