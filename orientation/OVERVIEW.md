# Bram: overview (Update 2026-11-02)

Bram is a desktop workspace for AI-assisted development, from the repository `judell/bram` on GitHub. Its README opens: "Agentic software development on human terms: legible, orderly, transparent, accountable, and collaborative." [`README.md:5-5`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L5-L5) It is for "Anyone who uses Claude Code, Codex, OpenCode and/or Antigravity." [`README.md:11-13`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L11-L13)

## What it is

The parts, in a short list:

- **A Tauri desktop shell in Rust.** It owns the pseudo-terminal, the agent process, turn-state detection and the push of events to the UI. [`docs/session-context-architecture.md:13-16`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/session-context-architecture.md?plain=1#L13-L16) Its entry point is `run()` in `src-tauri/src/lib.rs`. [`src-tauri/src/lib.rs:97044-97044`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L97044-L97044) At this commit `lib.rs` is 100,932 lines (`git show e8a38ac0:src-tauri/src/lib.rs | wc -l`), beside `guard.rs`, `guard_policy.rs`, `worklist_state.rs`, `search_index.rs` and `grant_lifecycle.rs`. `docs/releasing.md` describes the host the same way: "The Rust host is large and carries most of Bram's logic". [`docs/releasing.md:3-5`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/releasing.md?plain=1#L3-L5)
- **A terminal with the agent CLI in it.** One of four CLIs, `claude`, `codex`, `opencode` or `agy` (Antigravity), run in a PTY and shown with xterm.js; optional to look at and closed by default. [`src-tauri/src/lib.rs:28412-28424`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L28412-L28424) [`README.md:19-25`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L19-L25)
- **An agent pane built in XMLUI.** The tabs are Worklist, Transcript, Sessions, Issues, Commits, Queue, Search, Alerts, History, Files, Settings, Tips, Context and Status. [`app/tools/Main.xmlui:727-770`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/app/tools/Main.xmlui?plain=1#L727-L770)
- **The Worklist gate.** Every change goes from proposal, to altered files, to a commit or a drop, "and hooks hold the agent to that order: no file alterations without an approved item, no commit without your approval." [`README.md:68-68`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L68-L68) That is the intended workflow, not the whole of what the guard enforces. For a file edit, the guard allows the tool when a proposed or applied item in `resources/worklist.json` declares the path, even before **Start**: "File-aware tools can pass because a proposed/applied item declares the path." [`docs/authorization.md:245-246`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/authorization.md?plain=1#L245-L246) The stronger check, that the item was approved, is only logged: `trace_would_deny_unaddressed` "records stronger approval findings ... These are observations, not denials." [`docs/authorization.md:246-249`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/authorization.md?plain=1#L246-L249) With no covering item and no opt-out, the guard denies. [`src-tauri/src/guard_policy.rs:72-74`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/guard_policy.rs?plain=1#L72-L74) Diagram 3 shows the same split. ## How it runs

You start Bram from the root of a git repo. "Anywhere else (your home directory, a folder that isn't a git repo, or a subfolder of one), Bram starts nothing and says where to start from." [`README.md:96-99`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L96-L99) `gh` powers the Issues tab. [`README.md:104-108`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L104-L108) Install is a script that "verifies the archive's SHA256 against the published `SHA256SUMS`". [`README.md:120-126`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/README.md?plain=1#L120-L126)

For developers, builds are debug builds, always: "Always `cargo build` (debug), never `cargo build --release`, when validating changes". [`docs/developing-bram.md:480-482`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L480-L482) Under the documented `./bram` symlink launch, everything under `app/` is served from disk, so pane edits show on reload; only `src-tauri/**` needs a rebuild and relaunch. [`docs/developing-bram.md:439-445`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L439-L445) Releases are cut by `scripts/bump.sh` and a `workflow_dispatch`-only GitHub workflow. [`docs/releasing.md:14-24`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/releasing.md?plain=1#L14-L24) See diagram 6. The symlink is gitignored as a "Local launcher symlink to the current debug build" [`.gitignore:26-27`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/.gitignore?plain=1#L26-L27); `scripts/build.sh` creates it after a successful build, with the comment "nothing else creates it". [`scripts/build.sh:118-123`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/scripts/build.sh?plain=1#L118-L123)

[`src-tauri/tauri.conf.json:26-28`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/tauri.conf.json?plain=1#L26-L28) Releases run `cargo build` and then `tar` only `bram` and `bram-guard`.
