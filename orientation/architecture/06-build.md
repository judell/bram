## app/ served from disk

`serve_app_file` "prefers an on-disk `app/` root, falling back to the `include_dir!` embedded tree only when no candidate directory exists." [`docs/developing-bram.md:427-432`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L427-L432) The candidates are `resource_dir/app`, then the executable's directory plus `app`, then its parent's `app` and `../Resources/app`; `resolve_app_root` takes the first that exists. [`src-tauri/src/lib.rs:20121-20142`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L20121-L20142) [`src-tauri/src/lib.rs:20144-20152`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L20144-L20152) Under the `./bram` launch the table in the development doc says `app/tools/**`, `app/__shell/**` and `app/vendor/**` go live on a pane reload with no rebuild; `main.js`, `index.html` and `styles.css` "relaunch the app" but need no rebuild; and `src-tauri/**` is the "only genuinely rebuild-gated path". [`docs/developing-bram.md:439-445`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L439-L445) Even after reload, "a full relaunch remains the clean-room validation". [`docs/developing-bram.md:474-478`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L474-L478)

## Embedded app tree

`static EMBEDDED_APP: Dir = include_dir!(...)`, with a comment that Tauri's own asset resolver is avoided because it "SPA-fallbacks unknown paths to index.html — disastrous for XMLUI's optional code-behind probes". [`src-tauri/src/lib.rs:28-34`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L28-L34) The staleness trap (#332): `build.rs` watches exactly one file under `app/` for rebuilds, so "a markup-only edit followed by `cargo build` recompiles nothing, and a raw-binary launch silently serves markup from an older vintage." [`docs/developing-bram.md:457-461`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L457-L461) The remedy is legibility, not rebuilds: `bram --embedded-app-hash` and `bram --hash-app-dir <path>` use one hash algorithm, and `/__app-info` reports `servingEmbedded`. [`docs/developing-bram.md:465-470`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/docs/developing-bram.md?plain=1#L465-L470) [`src-tauri/src/lib.rs:20154-20162`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L20154-L20162)

The bundle setting is not used by any shipped form. `tauri.conf.json` lists `../app` under `bundle.resources`, and `bram_app_root_candidates` checks `resource_dir/app` first. [`src-tauri/tauri.conf.json:23-28`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/tauri.conf.json?plain=1#L23-L28) [`src-tauri/src/lib.rs:20128-20130`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/src-tauri/src/lib.rs?plain=1#L20128-L20130) The release workflow, however, copies only the `bram` and `bram-guard` executables into the archive, so a user who extracts it has no adjacent `app/`. [`.github/workflows/build.yml:276-281`](https://github.com/judell/bram/blob/e8a38ac08d3ac3a6323b712bb00ebf23aa4a0f05/.github/workflows/build.yml?plain=1#L276-L281) Releases run `cargo build` and `tar` only the two executables, so the runtime falls back to the embedded tree.
